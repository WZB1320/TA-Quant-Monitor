日期：2026-10-21 ｜ 状态：待拍板，未动任何代码
基线：`pre-adjust-20261016`（+123.26%，229 笔，快照 `data/baseline_snapshot_20261016.db`）

## 0. 一个决定方案体量的推论（先读这个）

**成交层切 raw 之后，信号层 qfq 的漂移问题自动消失。**

- qfq 漂移的本质 = 每次除权后整段历史乘一个常数（实测 600519 −2.31%、300308 −0.15%，全序列均匀缩放）；
- 信号层全部是比例型/尺度不变指标——已两次实测：整序列 ×3.7 / ×91.3 信号 100% 一致；
  滚动基准 vs 静态 qfq 得分差 2.91e-14；
- 漂移唯一能伤害的对象是"绝对金额"（成交价、股数、市值、NAV），而这批东西全部搬去 raw 层了。

结论：**信号层一行不用改**。原方案 2 里"信号层换 hfq + 滚动复权构造"整个砍掉。
你选 qfq 而不是 hfq 反而是更省的路线，数学上站得住。

唯一残余威胁：**跨批次拼接的台阶**——缓存里 38/46 只标的是 9 个抓取批次拼的，
拼接点两侧 qfq 基准不同，序列内部有台阶。这不是复权问题，是数据完整性问题，
用"回测窗口单批次保证"解决（批次 3）。

## 1. 目标形态

```
                    ┌─ 信号层: qfq (现状不动)
数据 (双轨) ────────┤      只产出比率: ATR/close, 止损距离/close, 距MA20百分比
 raw + qfq          │
 事件表 (D, s) ──┐  │
                 ▼  ▼
              成交层: raw + 事件日处理
              - T+1 成交价 = raw open
              - 除权日: shares×=(1+s), cash+=D×shares×(1−税率)
              - 涨跌停基准 = 除权参考价 (prev_close−D)/(1+s)
              - NAV / 持仓市值 = raw close
```

跨界只保留"比率接口"一个约定：信号层传 `ATR/close`、`止损距离/close`，
成交层用 raw 价格自行还原成元。**不做"5 个跨界点逐处除 K_t"**——
比率接口从结构上消灭"新代码忘记换算"的可能，不靠纪律。

### 批次 1：成交层切 raw + 事件日处理

### 批次 3：数据完整性 + 新基线 + 归因

- 回测模式强制单批次：BACKTEST 模式下取数全量重拉一次（46 只约几分钟），
  或沿用基线脚本的冻结快照机制；禁止跨批次切片
- 重跑基线，tag `raw-ledger-YYYYMMDD`
- 逐笔差异归因到 4 个来源：①一手取整路径分叉 ②红利税 ③佣金最低阈值 ④除权日涨跌停判定变化。**不允许出现"不明原因"**

**预期变化（先说清，免得吵"为什么结果全变了"）**：
- 总收益下修约 **1pp 量级**（红利税 + 整手粒度），不是十几个点——
  价格与股数同步失真、乘积抵消的结论已实测过（资本加权敞口 19.06 万·年）

  qfq→raw 尺度变化 5~9% 会让相当比例交易跳一手
- **验收不要求逐笔对得上旧基线**，只要求差异可归因

## 3. 待拍板 3 点

### 3.1 红利税建模程度（2026-10-22 实测后，推荐由 B 改为 C）

先正名：**"统一 10%" 统一的是税率，不是派息金额。** 派息金额 D 一律取公告真实值，三个方案都一样。

**实测证据（基线 229 笔 + 东财分红明细）：**

| 事实 | 数值 |
|---|---|
| 持仓天数 mean/p50/p75/p90/**max** | 29 / 24 / 42 / 60 / **103 天** |
| 最长持仓 < 1 年 | → **0% 档在本策略永不触发** |
| 资本加权档位占比 | ≤1月(20%) **35.0%**；1月~1年(10%) **65.0%** |
| 资本加权综合税率 | **13.49%**（≠ 10%，统一10%低估 3.49pp 税基） |
| 窗口内事件(12 只/39 个) | **全部纯派息，零送股零转增**；公告"扣税后"隐含税率 **39/39 = 10.00%** |
| 加仓结构 | 无 `add_position`，区间重叠 **0 对** → 单一 lot，`holding_days` 已在记录里 |

**关键机制（推翻我此前的成本估计）**：财税〔2015〕101号规定持股 ≤1 年的
**派息时不扣缴，待卖出时按先进先出算持股期限再扣收**——即税率在**卖出时**才确定。
回测里卖出日期已知、`holding_days` 已算好、且无加仓，**三档实现就是一行**：

```python
rate = 0.20 if holding_days <= 30 else 0.10   # 0% 档因 max 103 天永不触发
```

| 选项 | 做法 | 量级（相对真实） | 结论 |
|---|---|---|---|
| A | 不建模 | 虚高 **0.39~0.77pp** of capital | 相对现有 qfq 基线**不是退步**（qfq 已隐含免税再投资），但**账本无法与券商流水对账**，违背"辅助真实下单"目标 |
| B | 取公告税后值（窗口内 = 含税×0.9） | 残差 **0.10~0.20pp** | 简单，但隐含假设"每笔都持有 1月~1年"，与策略实际 35% 敞口 ≤1月 不符 |
| **C** | **按 `holding_days` 三档** | **0（精确）** | **推荐**。成本仅一行，且窗口内 39/39 事件可用公告值交叉验证 |

**残余复杂度（已知，二阶）**：`reduce_position` 分批卖出时，各批持股天数不同、
理论上有 FIFO 分档问题。20% vs 10% 在小额股息上是二阶小量，本期按整笔 `holding_days` 处理并显式标注。

### 3.4 事件表落库位置 —— 已定：进现有 `data/kline_cache.db`（不新建库文件）

现有库已含 `kline_cache`（40130 行，PK `(symbol,date,adjust)`）与迁移备份表
`kline_cache__old_20261015084611`，原地加表有先例、风险可控。

选 DB 的理由**不是容量**（46 只 × 3 年 ≈ 200 条；存 baostock 全历史 ≈ 700 条，JSON 完全装得下），而是：
① 回测要按 `(symbol,date)` 与行情 join，同库一条 SQL；
② 哨兵是本地零成本查询；③ 事件表与行情必须同批次同口径，放一起天然保证。

弱点与对策：**DB 不能 git diff、不可审阅** → 每次校验导出 JSON 供审阅，裁决结果回写 DB 并在 `reason` 列留痕。

```sql
CREATE TABLE corporate_action (
    symbol          TEXT NOT NULL,
    ex_date         TEXT NOT NULL,       -- 除权除息日
    record_date     TEXT,                -- 股权登记日：entry_date <= record_date 才有权领取
    dps_pre         REAL,                -- 每股派息（含税，元）  <- 计算基数
    dps_after       REAL,                -- 每股派息（税后，元，公告值） <- 仅校验/送股兜底
    share_ratio     REAL DEFAULT 0,      -- 送股比例 s
    transfer_ratio  REAL DEFAULT 0,      -- 转增比例
    multiplier      REAL,                -- 复权乘数：行情反推（裁判值）
    mult_baostock   REAL,                -- baostock 因子比值
    mult_em         REAL,                -- 公告重构值
    verified        INTEGER DEFAULT 0,   -- 1=三方闭合(<0.01元) 0=待裁决
    reason          TEXT,                -- 未闭合原因，如"因子有明细无→疑似配股"
    checked_at      TEXT,                -- 本条最后校验时间 —— 过期哨兵用
    PRIMARY KEY (symbol, ex_date)
);
```

**派息基数口径（与 C 方案联动，必须遵守）**：税率既按 `holding_days` 自算，
基数就必须用**含税 `dps_pre`**，不能用公告税后值（后者恒定按 10%，而实际综合税率 13.49%）。
例外：`share_ratio > 0` 时改以 `dps_after` 为基数（送股按面值 1 元/股代扣的税已内扣），
不再叠加自算税率。窗口内 39/39 事件 `share_ratio = 0`，此分支本期不触发。

### 4.2 已排除的疑虑（查过代码/数据，非缺口）

- **涨跌停板块差异**：`broker.get_limit_pct(symbol)` 已实现科创板/创业板 20%、

### 4.3 必须补强的 4 点（并入对应批次）

1. **止损价的除权日语义**（批次 2 的实现约束）：若止损/移动止盈存的是**绝对价快照**，
   除权日必须同步调整，漏一处就回归"除权日误止损"。正确实现：止损价**每日由
   `cost_price × (1−d)` 现算**——cost_price 已随送转同步调整（批次 1），
   则百分比语义天然连续，**无需除权日特判**。比率接口必须按此约定实现。
2. **送股与转增要拆开**（批次 0 事件表）：税务不同——送股按面值 1 元/股征 10%
   （从派息中代扣），转增不征。东财明细已有独立列
   （`送转股份-送股比例` / `送转股份-转股比例`），可拆。影响量级极小
   （送股税 = 0.1 元/股），但账本必须显式标注。
3. **派息日不可得**（批次 0 简化标注）：东财明细只有除权除息日/股权登记日，
   **没有派息日字段** → "分红现金延迟到账"无法建模。显式简化为
   **除权日现金即可用**（实盘到账晚 2~5 天，对年化收益影响 <1bp，可忽略）。
   附带数据红利：明细描述字段直接给含税/税后双值
   （如"派4.50元(含税,扣税后4.05元)"）——若红利税选 B 方案，税后值可直接取公告，
   比自算更贴近实际执行。
4. **配股需要显式账本政策**（批次 0 出数后拍板）：三方校验会暴露
   "因子有、明细无"的配股/增发事件。遇到时二选一且必须显式：
   参与配股（`cash -= 配股价 × shares × 配股比`，shares 同步增加）或
   放弃配股（shares 不变、接受稀释）。46 只池 2024-26 有无配股标的，待批次 0 清单。

### 4.4 一个不能丢的后续实验（批次 3 之后，独立立项）

**qfq vs hfq 的信号边界稳定性对比**。本轮检查确认：hfq 相对舍入精度比 qfq 高
约 100 倍（2500 元 vs 26 元价位上的 2 位小数）。之前实测"qfq vs hfq 逐日得分
仅 24.14% 完全一致"的根因正是 qfq 的相对舍入被 EMA/MACD/KDJ 递归放大——
**这意味着信号档位边界当前坐在 ~4e-4 的噪声上**。方案选 qfq 是为了归因干净，
但"切 hfq 降噪"是一个独立的、有价值的后续实验，不并入本次改造。
