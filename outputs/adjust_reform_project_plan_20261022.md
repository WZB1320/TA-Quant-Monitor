## 0. 一页纸摘要

### 目标
1. **成交层真实化**：成交价、股数、现金、市值、NAV 全部改用不复权（raw）行情，使每笔交易可手算对账。
2. **事件层补齐**：送股/转增调整股数，现金分红进现金账，按持股期限计红利税。
3. **可复现**：消除 qfq 随新除权漂移导致的历史不可重放。

### 非目标（明确不做）
- **不动信号层**。信号继续用 qfq，一行不改。
- **不追求"更精确"的复权因子**。已实测精度被"一分钱"封顶（max 偏差 0.0066 元）。
- **不做多源数值融合**。多源只用于交叉校验，输出单一值。
- **不引入东财/腾讯行情源**（单位地雷：东财成交量单位是手、腾讯 `amount` 列实为成交量）。
- **不建模派息到账延迟**（明细无派息日字段，影响 <1bp）。

### 里程碑

| ID | 里程碑 | 关键产出 | 可独立交付 |
|---|---|---|---|
| **M1** | 数据基座 | `corporate_action` 表 + raw 双轨 + 三方校验报告 | ✅ 不动交易逻辑 |
| **M2** | 成交层真实账本 | 成交/市值/NAV 切 raw + 事件日处理 + 红利税 | ✅ |

**每个里程碑独立验收、可随时停。** M1 完成即可交付审计能力，不依赖后续。

## 1. 核心设计

### 1.1 口径分层（唯一契约）

```
                  ┌── 信号层: qfq  ── 只产出比率，不出绝对金额
行情双轨 ─────────┤
 raw + qfq        │   ATR/close、止损距离/close、距MA20百分比
                  │
事件表 (D, s) ─┐  │
               ▼  ▼
             成交层: raw + 事件日处理
             - T+1 成交价 = raw open
             - 除权日: shares ×= (1+s)；ref_price = (ref_price − D)/(1+s)
             - 现金: cash += D_pre × shares；平仓时扣红利税
             - 涨跌停基准 = 除权参考价 (prev_close − D)/(1+s)
             - NAV / 持仓市值 = raw close
```

**跨界唯一约定：信号层只传无量纲比率，成交层用 raw 价格自行还原成元。**
不做"逐处除以换算系数 K_t"——比率接口从结构上消灭"新增代码忘记换算"的可能，不靠纪律。

### 1.2 为什么信号层用 qfq 而不是 hfq（已决策，勿再改）

切 raw 之后，**qfq 漂移问题自动失效**：

- qfq 漂移 = 每次除权后整段历史乘一个常数（实测 600519 −2.31%、300308 −0.15%）
- 信号层全是比例型指标，实测整序列 ×3.7 / ×91.3 信号 **100% 一致**；滚动 vs 静态基准差 2.91e-14
- 漂移唯一能伤害的是绝对金额，而绝对金额已全部搬去 raw

选 qfq 而非 hfq 是为了**保住与基线的可比性**——否则"复权改造"与"精度变更"两个变量混进同一次归因，结果无法解释。

### 1.3 红利税：按持股期限三档（已决策）

| 持股期限 | 税率 | 依据 |
|---|---|---|
| ≤ 1 个月（含） | **20%** | 财税〔2015〕101号，全额计入应纳税所得额 |
| 1 个月 ~ 1 年（含） | **10%** | 暂减按 50% 计入 |
| > 1 年 | **0%** | 免征 |

**实测支撑（229 笔基线）**：持仓 mean 29 / p50 24 / **max 103 天** → **0% 档永不触发**；
资本加权综合税率 **13.49%**（≤1月档占 35.0%，1月~1年档占 65.0%），不是 10%。

**关键机制**：持股 ≤1 年的**派息时不扣缴**，待卖出时由中登按先进先出算持股期限、券商从资金账户扣收。
即**税率在卖出时才确定**——回测里 `holding_days` 已算好，实现只需一行：

```python
rate = 0.20 if holding_days <= 30 else 0.10   # 0% 档本策略不触发
```

### 1.4 派息基数口径（易错点，必须遵守）

税率既按 `holding_days` 自算，基数就必须是**含税 `dps_pre`**——
公告的"扣税后"值恒定按 10% 算（窗口内实测 39/39 事件隐含税率 = 10.00%），与实际 13.49% 不符。

| 场景 | 基数 | 税率来源 |
|---|---|---|
| `share_ratio == 0`（**窗口内 39/39 全是这种**） | `dps_pre` | `holding_days` 三档自算 |
| `share_ratio > 0` | `dps_after` | 不再叠加（送股按面值 1 元/股代扣的税已内扣） |

### 1.5 除权处理顺序（决定正确性）

**除权调整必须在当日止损检查之前执行。** 顺序对了，"除权日误止损"根本不会发生，无需特判：

```
除权日 prev_close = P，派息 D → 除权参考价 (P − D)/(1+s) ≈ 当日 raw 价格
同时 ref_price 同步调整为 (ref_price − D)/(1+s)
故 硬止损判据 current_price <= ref_price × (1 − 12%) 天然不成立
```

反之若 `ref_price` 不调整，价格跳空 D 会被当成暴跌 → 误触发止损。这是本次改造**最关键的一处正确性**。

## 2. 数据模型

### 2.1 `corporate_action` 表（落 `data/kline_cache.db`，不新建库文件）

现有库已含 `kline_cache`（40130 行）与迁移备份表，`_init_db` 已有成熟的迁移范式可复用。

```sql
CREATE TABLE IF NOT EXISTS corporate_action (
    symbol          TEXT NOT NULL,
    ex_date         TEXT NOT NULL,      -- 除权除息日
    record_date     TEXT,               -- 股权登记日：entry_date <= record_date 才有权领取
    dps_pre         REAL,               -- 每股派息（含税，元）  <- 计算基数
    dps_after       REAL,               -- 每股派息（税后，元，公告值） <- 仅校验/送股兜底
    share_ratio     REAL DEFAULT 0,     -- 送股比例 s（每1股送几股）
    transfer_ratio  REAL DEFAULT 0,     -- 转增比例
    multiplier      REAL,               -- 复权乘数：行情反推值（裁判）
    mult_baostock   REAL,               -- baostock backAdjustFactor 逐行比值
    mult_em         REAL,               -- 东财明细重构值 prev/((prev−D)/(1+s))
    verified        INTEGER DEFAULT 0,  -- 1=三方闭合(<0.01元) 0=待裁决
    reason          TEXT,               -- 未闭合原因，如"因子有明细无→疑似配股"
    checked_at      TEXT,               -- 本条最后校验时间 —— 过期哨兵用
    PRIMARY KEY (symbol, ex_date)
);
```

| 模块 | 职责 |


### D.4 为什么 M3 必须并入 M2（关键）

原计划 M2 只切成交价、M3 再改 ATR。但这两步**不能分开做**：

- M2 后 `entry_price` 是 raw 尺度，而 ATR 由信号层用 qfq 序列算出 → 二者差一个复权常数
- `shares = risk / (ATR × mult)`，ATR 偏大 K 倍则仓位偏小 K 倍（实测 qfq/raw 差 5~9%）
- 即 M2 单独上线会在**仓位**上引入一个 5~9% 的静默误差，且它看起来"只是参数不一样"

故改为：`atr_ratio = ATR / close`（无量纲）跨界，成交层用 `ratio × ref_price` 现算成元。
副产品是**止损距离在除权后自动随 `ref_price` 下移**，不再需要逐个修正止损价。

### E.7 全量暴露的判据缺陷：半分边界假报警

抽样 10 笔全绿，全量却报出 3 笔 0.01 元差异。根因**不是账本错误**：

| 标的 | 计算值（源） | 记录值（源） | 源值差 | 各自 round 到分 |
|---|---|---|---|---|
| 000725 2026-01-08 | −32.93499999999999 | −32.935 | 1e-14 | −32.93 vs **−32.94** |
| 600875 2026-04-24 | −1284.4250000000013 | −1284.425 | 1e-12 | −1284.43 vs **−1284.42** |
| 600887 2026-07-17 | −210.76504600000112 | −210.765 | 4.6e-5 | −210.77 vs **−210.76** |

三笔 pnl 的精确值**都落在 `x.xx5`（半分）上**，浮点表示在边界两侧差 1e-14 ~ 1e-12，
`round` 到分的进位方向相反，于是报出 0.01 的"差异"。第三笔还叠加了导出侧
`round(pnl, 4)` 丢掉的 4.6e-5 尾数。

**修正：差异判定必须在源值上做，而不是在舍入之后。** 两步判据：

1. `|源值差| <= EXACT_TOL` → 通过（两值同源，分位不同只是边界巧合）
2. 否则退化为分位比对 → `|Δ| <= 0.005` 才算过

`EXACT_TOL = 1e-4`，不是拍脑袋：它必须覆盖**导出侧自身的精度损失**
（`pnl`/`dividend_*` 是 `round(,4)`，单笔最大 5e-5；`entry_amount` 是 `round(,6)`），
同时比 1 分钱小 100 倍，吞不掉真错。commission 的 0.0049 级噪声超过该阈值，
会**正确退化**到分位分支而不是被无脑放行 —— 此行为由
`test_source_diff_above_1e4_still_falls_back_to_cent_compare` 锁定。

**绝不能用 0.01 容差一刀切**：那会把真实的 1 分钱错误一起吞掉，
`test_real_one_cent_error_is_caught` 就是防这个的。

宁可不出报告，也不给一份精确的错报告。

### F.5 测试

`tests/unit/test_raw_baseline_attribution.py` 8 个用例，锁定"四类加和 = 实际 delta"这一不变量，
其中 `test_unexplained_residual_is_reported_not_hidden` 人为注入 99 元误差，
断言必须被判为不守恒 —— 防止将来口径改了而归因公式没跟上时静默通过。

**一处由测试暴露的公式缺陷**：初版 `e_div = dividend_gross − dividend_tax` 假设
legacy 臂分红恒为 0（真实成立），但公式不该依赖该前提。改为差值形式
`(raw_gross − raw_tax) − (legacy_gross − legacy_tax)`。真实场景下二者代数等价，
故已产出的基线归因结果无需重跑。

### C.4 实施中修正的三处判据缺陷（原方案未覆盖）

1. **误差量纲错**：原用 `|Δ乘数| × 前收`，送转事件下被 `mult²` 放大。
   实测 001309 误判 0.0129 元，实际除权参考价只差 0.0076 元。
   改为 `|前收/mult_a − 前收/mult_b|`。
2. **baostock 占位行**：4 条 `mult_b=1.000000` 的空事件被当成"疑似配股"。改为 `|mult_b−1|<1e-9` 且无他源支持则丢弃。
3. **单边召回不足**：候选日期原只取行情检出，小额派息（600392 每股 0.02 元）低于行情阈值被漏掉。改为三源并集 ±7 天聚类。

### C.5 一个原方案未预见的会计事实：公告派息 ≠ 价格调整

回购股份不参与利润分配时，两者不等，且**两者都对**，用途不同：

| 用途 | 取值 | 例：600519 2025-06-26 |
|---|---|---|
| **现金账**（股东实际到账） | 公告 `dps_pre` 每股 27.6730 | `cash += 27.6730 × shares` |
| **成本基准 / 最高价 / 除权参考价** | 市场乘数反解 27.6007 | `ref_price /= multiplier` |

差额 0.0723 元是回购股（占比 0.26%）放弃的那份，由其余股东无偿获得。
原先若用公告值调成本基准、或用行情值记现金，都会错。

**方向相反的例外必须人工裁决**：若行情价格调整**大于**公告派息（603259），
"回购股不参与"解释不了（它只会让调整变小），无法判断实际到账现金 → 判未闭合。
